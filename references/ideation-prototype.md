# 解決案・体験の試作・検証

根拠：第7章 pp.147-163、第8章 pp.165-200、第9章 pp.225-232。

## 発想と選択を分ける

まず「誰にどんな体験をもたらすか」を考え、その実現手段を複数挙げる。観察から離れて便利そうな機能だけを増やさない。発想の途中で採算や新奇さを理由に全て切り捨てず、比較する段階を分ける。

資源は技術だけではない。人、場所、既存製品、知識、ネットワーク、知財、運用も含む。本書のSWOTの使い方は、自分たちと社会の資源・環境を可視化し、問題と資源を異質に組み合わせて解決・市場機会を探ること。四枠に単語を入れただけで終えない。

カタログや画像、キーワード、希望点・欠点の列挙は新しい組合せの刺激に使う。見つけた別分野の事例を、そのまま同じ効果が出る根拠にしない。

候補が似通うときは、提供方法、担当者、タイミング、情報の見せ方、購入・支払方法、モノとサービスの組合せを変える。数の目標は依頼の規模次第で決める。

## 比較とリフレーミング

有用性、実現性、事業性を根拠とともに比較する。未検証なら未検証と記す。順位は実験結果に応じて更新する。

本書の探索マップは体験の新規性と技術・機能の新規性で見る。見慣れないために評価できない案を、単に悪い案としない。低コストで確かめられるなら、常識的な案と別にダークホースも試す。未検証の新奇案へ大きな投資を進める根拠にはしない。

6つの帽子は全員が同時に同じ視点（事実、感情、困難、可能性、創造、全体整理）に切り替える。AIが行う場合は視点の点検と表現し、実際の専門家の合意とは言わない。パワーオブテンは時間・空間・対象範囲を拡大／縮小して問題の枠を点検する。

## 何を作るか

| 分からないこと | 小さく作るもの |
|---|---|
| 望む体験が伝わるか | 状況→困りごと→働きかけ→変化の絵コンテ、スキット |
| いつどこで困るか | 現状のCJM：行動・発言・感情・環境・ペイン／ゲイン |
| 提供後の流れが成立するか | 望ましいCJMと、利用前・中核・利用後の接点 |
| 裏側の運用が回るか | サービス・ブループリント：顧客行動、接点、表側対応、裏側業務、支援資源 |
| 特定機能の効果があるか | 紙・既存道具等によるクリティカル・ファンクショナル・プロトタイプ |
| 操作や説明が理解されるか | 必要な場面だけの画面・説明カード・手順書 |

CJMとサービス・ブループリントは別物。前者は顧客の時系列体験、後者は体験を実現する提供側との関係を捉える。

本書の3R：Rough（粗く）、Rapid（素早く）、Right（検証したい側面を正しく表す）。見た目を作り込むほど学べるとは限らない。愛着や製作費で変更できなくなる前に試す。

## 検証カード（実務補足）

`仮説｜根拠｜対象と場面｜試作品｜提示する課題｜観察・質問｜成功・変更・中止の条件｜費用・時間上限｜次の判断`

仮説が不明なままMVPを作らない。需要、使いやすさ、技術成立、支払意向、採算など、何を確かめるかを分ける。

行動が完了するか、迷いや回避が減るか、どこで止まるかを観察する。「良いですね」という感想や好意的な回答だけで需要を証明しない。時間、失敗、選択、継続なども目的に合うときに記録する。

人数・閾値を根拠なく普遍的ルールにしない。探索の小人数テストと、市場出現率や因果効果の検証を区別する。数値は提案・実測・仮置きに分ける。

## 結果から進路を変える

- 期待した反応が得られた：誰・どの条件に限るかを示し、別条件や反復利用を確かめる。
- 反応が弱い：問題が違うのか、解決手段が違うのか、提示方法・試験条件が悪いのかを分ける。
- 続ける根拠が薄い：小さな追加確認で変わるかを見て、変更・中止を判断する。

同じ仮説に新情報がないまま改善を無期限に繰り返さない。許された期間・予算内で、得たことと残る不確実性を示す。
